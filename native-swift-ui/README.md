# Voys (native SwiftUI)

A native iOS rebuild of the Vialer/Voys app, built as the Voys brand. Calling uses the iOS phone lib from
`../../flutter-phone-lib/ios/flutter_phone_lib`, copied into `PhoneLib/`. See `SHORTCUTS.md` for
everything that was simplified or deferred in this first pass.

## Requirements

- Xcode 26 or newer (built with Xcode 27.1), iOS 17 deployment target
- [xcodegen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)

## Build and run

```sh
cd native-swift-ui
xcodegen generate          # regenerates Vialer.xcodeproj from project.yml
open Vialer.xcodeproj
```

Pick a brand by choosing its scheme: `Voys`, `Vialer`, `VialerStaging`, `Verbonden` or `ANNAbel`.
Each scheme has its own `Debug-<Brand>`/`Release-<Brand>` configurations that set the bundle id,
display name, app icon and the `BrandIdentifier` Info.plist value that `Brand.current` reads.

Or from the command line:

```sh
xcodebuild -project Vialer.xcodeproj -scheme Voys -configuration Debug-Voys \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

Swift packages (linphone SDK 5.4.24, Swinject 2.10.0 and the local `LinphoneWrapper`) resolve on
first build. VoIP push and CallKit need a real device with the `com.voys.app` provisioning
profile; the simulator reaches the login screen and the rest of the UI but can't receive calls.

## Strings

UI strings are pulled from Phrase into `Vialer/Resources/Localizable.xcstrings` and wrapped in typed
accessors (`L10n.…`) generated by `scripts/generate_l10n.py`:

```sh
phrase pull -t "$PHRASE_ACCESS_TOKEN"
python3 scripts/generate_l10n.py
```

Strings only the native app needs (`native.*`, read via `N("key")`) live in
`Vialer/Resources/Native.xcstrings`, an ordinary String Catalog edited in Xcode; nothing is pushed to
Phrase.

## Third-party keys

`scripts/generate_env.sh` (run as a build phase) writes the Sentry DSN, Segment write key,
Logentries token and feature flags from the repo's `.env` into the gitignored
`Vialer/Generated/Env.swift`. Leave a key empty to run without that service.

## Layout

```
project.yml                 xcodegen project definition (bundle id, plist, entitlements)
Vialer/
  App/                      VialerApp (entry point), AppContainer (composition root)
  Config/Brand.swift        hard-coded Voys production URLs and names
  Core/                     HTTP client, keychain, UserDefaults store, logging stubs, RES client
  Data/Models               User, Destination, CallRecord, Colltacts, Settings
  Data/API                  VoipgridAPI, UserStatusAPI, SharedContactsAPI, CallwakerMiddleware
  Domain/                   SessionManager, CallManager, PresenceManager, ColltactsStore, RecentsStore
  Features/                 Onboarding, Dialer, Call, Recents, Colltacts, Settings views
  Shared/                   Theme and reusable components
  Resources/                app icon, ringtones, missed-call strings, privacy manifest
PhoneLib/
  iOSPhoneLib/              copied PIL + linphone wrapper (compiled into the app)
  LinphoneWrapper/          local Swift package with the linphone type aliases
```

## What's implemented

Login (incl. forced password change and two-factor), permission onboarding, mobile number,
dialer with T9 search, VoIP calling via CallKit (mute, hold, DTMF keypad, audio route picker,
attended transfer and merge), VoIP push registration with Callwaker, recents (personal and
client-wide, missed filter, call details), device contacts, shared contacts (add/edit/delete),
colleagues with live presence over Resgate, availability status and ringing device, app
preferences, user settings (mobile number, business number, change password), about, logout,
`vialercall://` URL scheme and Siri call intents.

## CI (Codemagic)

The `native-swift-ui-voys` workflow in the repo's `codemagic.yaml` builds a development-signed
Voys `.ipa` on every push to `native-swift-app` (and on demand) via
`utils/ci/codemagic/bin/build_native_ios.sh`: it writes the `.env` from Codemagic's variables, runs
xcodegen, fetches development signing files for `com.voys.app` and archives the `Release-Voys`
configuration. The `.ipa` is kept only as a build artifact and installs on devices registered to
the team; the workflow has no publishing step, so nothing goes to TestFlight or the App Store.
Strings are built from the committed `Localizable.xcstrings`; run the Phrase pull locally when they
change.
